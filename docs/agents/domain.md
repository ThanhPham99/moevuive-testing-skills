# Domain Docs

This repo uses a **single-context** domain documentation layout:

- Root glossary: `GLOSSARY.md`
- Architecture Decision Records (ADRs): `docs/adr/`

## Consumer Rules

1. Read `GLOSSARY.md` before authoring specs, skills, rules, or workflows so canonical domain terms are used consistently.
2. Do not put implementation details or file paths into `GLOSSARY.md`.
3. Consult `docs/adr/` when modifying architectural seams or cross-cutting conventions.
